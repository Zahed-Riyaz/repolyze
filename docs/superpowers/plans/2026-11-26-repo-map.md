# Repo Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A map of the repo on the Repo tab that shows where the app starts, its core files and a numbered reading path, with an on-click AI explanation in Ask, plus secondary contribution lenses.

**Architecture:** One new classic script, `territory.js`, holding pure functions (entry detection, load parsing, graph ranking, treemap layout, folder stats/classification, role parsing), one crawler (`buildImportGraph`) and one PR loader (`loadTerritory`), and the DOM renderer (`renderTerritory`). `sidepanel.js` calls it from the Repo tab loader; `ask-focus.js` gains a `map` focus kind; `brief.js` gets a mini map. Shared `parseImports` / `resolveImport` are not changed.

**Tech Stack:** Plain JS (classic scripts, no build), Chrome MV3 side panel, GitHub REST + raw.githubusercontent.com, inline SVG, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-26-repo-map-design.md`

## Global Constraints

- No build, no libraries, no new permissions. `territory.js` is panel-only (never in `background.js`'s `importScripts`).
- Script order: `territory.js` loads after `stack.js` and before `sidepanel.js` in `sidepanel.html`, `test/helpers/panel.js` `SCRIPTS`, and is added to `npm run check`.
- GitHub API calls only via `fetchGitHub` / `fetchGitHubPage`; sorted lists always pass `direction=desc`. File contents only via `readRepoFile`.
- Everything interpolated into `innerHTML` goes through `escapeHtml`; async renders check `isCurrentRepo(key)`.
- Opening a repo still costs **4** API requests; opening an issue brief still **2**; How it runs on a public repo costs **0** API requests; no AI call without a click.
- Crawl caps: **300** files public, **60** private (private only after a click). Reading path ≤ **8** steps. Core: top **10** with ≥ **3** importers. Monorepo entries capped at **6**.
- Contribution sample: signed in **20** closed (outsiders first) + every open PR up to **30**; signed out **6** + **4**. Welcoming: < **3** PRs → not enough data; ≥ **60%** outside merged and median outsider days ≤ **14** → good; < **30%** → bad; else neutral "mixed".
- Colours from `theme.css` tokens; respect `prefers-reduced-motion`. Copy follows CLAUDE.md §5 (sentence case, fragments joined with " · ").

## Review Focus

- **Truncated tree** (GitHub returns `truncated: true` on huge repos): map still draws what it has and says "Large repo — some files not listed". Test in Task 3.
- **Import cycles** (`a` imports `b` imports `a`): crawl terminates, each file read once. Test in Task 3.
- **A file read fails mid-crawl** (404 or network): skipped, crawl continues, not counted as reached. Test in Task 3.
- **Switching repos during a crawl**: nothing draws into the new repo, and the old crawl stops queuing reads. Test in Task 6.
- **AI answer without a `roles` block** (or a malformed one): map unchanged, answer renders normally, no error. Test in Task 7.

### Task 4: Core and reading path

**Files:**
- Modify: `territory.js`
- Test: `test/territory.test.js`

**Interfaces:**
- Consumes: `Graph` (Task 3), `TEST_PATH` (`retrieval.js`).
- Produces: `rankCore(graph) → [{ path, importers }]` — ≤ 10, `importers ≥ 3`, no tests (`TEST_PATH`), no `.d.ts`, barrels counted through (a file whose non-blank lines are all `export … from` passes its in-degree to what it re-exports and is itself left out).
- Produces: `readingPath(graph, core) → [{ step, path, reason }]` — ≤ 8 steps.
- Produces: `globalScripts(graph) → string[] | null` — when the strongest entry is an HTML page with ≥ 3 scripts in `order` and those scripts have no edges between them, its scripts in load order; else `null`.

Reading path rule (not determined by the signature):

```
path = [strongest entry]
while path.length < 8:
  candidates = files imported by any file already in path, not yet in path
  if none: break
  take the candidate with the highest inDegree; ties → smaller depth → path order
if path.length < 8: append core files not in path (by importers) until 8 or core runs out — but only if path.length ≥ 6 when the loop ended; else append them all up to 8
```

If `globalScripts(graph)` is not null, the path is the HTML page followed by its scripts in load order (≤ 8) and `rankCore` returns the largest of those scripts by size (top 3, `importers: 0`, reason "largest script").

Reasons: entry → `"entry point · " + entry.reason`; others → `"loaded by ① app.ts · imported by 23 files"` (circled number of the earliest step that imports it; omit "imported by" when 1); global scripts → `"script 3 of 12 on sidepanel.html"`.

**Interfaces:**
- Produces: `mapNodes(paths: [{path, size}], root: string) → [{ path, bytes, children: [{ path, bytes }] }]` — the folders and files directly under `root` (sized by summed code bytes, skipping `NOISE_PATH`/`NOT_CODE`), each with its own children one level down; root-level files grouped as `{ path: "(root files)" }`; blocks < 1.5% of the total merged into `{ path: "…", label: "N smaller folders", merged: [paths] }`.
